# Support

## Getting Help

LCDD is an open specification project. Here's how to get help:

### Questions and Discussion

- **GitHub Issues:** For questions about the specification, methodology, or adoption. [Open an issue](https://github.com/livingcontext/living-context-driven-development/issues/new).
- **GitHub Discussions:** For broader conversations about constraint governance, AI-assisted development, and related topics (available when Discussions are enabled).

### Reporting Issues

- **Specification bugs:** If you find an inconsistency, ambiguity, or error in the specification, open an issue with the `spec-bug` label.
- **Documentation issues:** Typos, unclear explanations, broken links — open an issue with the `documentation` label.
- **Security vulnerabilities:** See [SECURITY.md](SECURITY.md). Do NOT open a public issue.

### Feature Requests

LCDD is in Specification Phase (v0.1.0). Feature requests for the methodology itself should follow the RFC process described in [CONTRIBUTING.md](CONTRIBUTING.md).

Feature requests for reference implementations (CLI, MCP server, VS Code extension) are welcome but may not be addressed until the relevant milestone (see [ROADMAP.md](ROADMAP.md)).

### Response Times

| Type | Expected Response |
|---|---|
| Bug report | Within 7 days |
| Question | Within 14 days |
| RFC proposal | Acknowledged within 7 days; decision within 30 days |
| Security vulnerability | Within 72 hours (see SECURITY.md) |

### Community

LCDD is a new project. The community is forming. The best way to participate is to open issues, contribute to discussions, and share the methodology with your network.

---

*This is a community-maintained open specification. There is no commercial support, SLA, or guaranteed response time.*
